# Source Watch: a bounded RegNav experiment

**Question:** when a source file changes, which linked statements should someone
reconsider before reusing a report?

This experimental, offline utility records SHA-256 digests of a small set of
local source files and compares their later bytes with that baseline. It returns
the claim identifiers linked to changed or unobserved files. The intended first
users are teams maintaining research reports or AI-assisted knowledge bases.
Whether those teams find it useful remains to be tested.

It is a separate experiment, not a change to the evidence-ledger schema or CLI.
The existing `regnav_evidence compare` checks two ledger records; this experiment
checks explicitly listed local files even when their recorded version label has
not been edited. Neither tool establishes legal accuracy.

## See a real generated result

Requires Python 3.10 or newer, with no packages, API key or internet connection.
From the repository root:

```bash
python experiments/source_watch/demo.py
```

The demo creates a fictional rule in a temporary directory, snapshots it, changes
its wording and prints the actual JSON report. It deletes the temporary directory
on completion and does not read your documents. The output must include
`RECHECK_REQUIRED`, `CHANGED_BYTES` and `training-claim-1`.
The [saved report](sample_report.json) was generated by that script, not authored
as pretend output. This demo makes no claim about any real law or customer.

## Use a manifest

In a trusted local directory containing `source.txt`, prepare a manifest:

```json
{
  "schema": "regnav-source-watch/0.1",
  "files": [
    {"id": "source-1", "path": "source.txt", "claim_ids": ["claim-1"]}
  ]
}
```

Paths are relative to the directory passed as `--root`, not to the manifest.
Claim identifiers are supplied by you; the utility does not discover or validate
which propositions a source supports. Keep private files and manifests outside
public repositories. Source filenames and claim identifiers appear in reports.

```bash
python experiments/source_watch/watch.py snapshot manifest.json --root ./sources --output baseline.json
python experiments/source_watch/watch.py check baseline.json --root ./sources --output observation.json
```

Choose new output filenames. An existing output is never overwritten. Preserve
the original baseline; create a new dated baseline only after the necessary review.
The utility never edits sources, the evidence ledger or human-review declarations.

| Result | Meaning | Exit code |
| --- | --- | --- |
| Snapshot created | Bytes of all listed local files were recorded | 0 |
| `UNCHANGED_BYTES` | All listed files match this baseline | 0 |
| `RECHECK_REQUIRED` | At least one listed source changed or was not observed | 2 |
| Input/output error | Invalid input, unavailable root or failed output operation | 1 |

Standard argument-usage errors also exit 2. A report's schema and observation
field distinguish a valid attention result from incorrect command usage.
`NOT_OBSERVED` is never silently treated as unchanged.

## Limits and security boundary

- A byte change may be a harmless formatting edit. A person decides relevance.
- Unchanged bytes do not establish current law, source authenticity, a complete
  source set, quotation accuracy, correct reasoning or a valid earlier review.
- The utility does not fetch websites, parse PDFs, monitor a URL, run continuously,
  provide an API/MCP service, send alerts or collect payments. A later adapter would
  require separate implementation and testing. The demo is not a hosted product.
- SHA-256 records content identity, not authorship, timestamp certification or
  tamper-proof history. Protect and version the baseline separately.
- Only listed files and supplied claim links are covered. Unlisted files and
  newly appearing authorities are outside the check.
- Use a trusted, stable local directory. Rejecting traversal and symlinks reduces
  accidental access; this is not a sandbox against a hostile process concurrently
  replacing files. Do not run untrusted directories with privileged credentials.
- Each file is limited to 16 MiB, JSON input to 1 MiB and manifests to 1,000 files.
  The tool reads bytes, including binary files, without interpreting their text.

## Verification and next evidence

Seventeen focused tests passed locally on Python 3.13.5 on 24 October 2026,
covering changed and missing sources, linked-claim selection, malformed manifests,
duplicate keys/identifiers, unsafe paths, symlinks, limits, non-mutation, exact
hashes and CLI exit/output protection. Remote CI must be inspected separately.
These are internal implementation checks, not independent adoption or a security
certification.

```bash
python -m unittest discover -s tests -p test_source_watch.py -v
```
