# Working on RegNav

Read the README, current roadmap, progress record and `docs/WORKSTREAMS.md`
before changing the project. Keep each change useful, bounded and reviewable.

- Preserve the offline, standard-library implementation unless a dependency has
  a concrete, documented benefit.
- Run the relevant regression tests and example commands. Record actual results
  and the Python version used. Do not invent a passing CI result.
- Treat `checked` as a person's declared review. An automated check must never
  be represented as legal verification or a completed human assessment.
- Keep fictional training material visibly labelled. Real legal examples need
  primary sources, exact pinpoints, jurisdiction and version information.
- Preserve existing rights and third-party attribution. Do not add a general
  reuse licence as part of routine maintenance.
- Update `docs/PROGRESS.md` and the next actionable item in `docs/ROADMAP.md`.
- Use branches and review the full diff. Respect concurrent changes and
  repository protections. Routine changes may be merged after verification
  under the maintainer's standing development instruction.
- Publish no private manuscripts, client or student data, account credentials,
  private financial plans or unsupported impact claims.

Write documentation in clear British English. State what the implementation
does, what evidence supports it and what remains to be evaluated.
